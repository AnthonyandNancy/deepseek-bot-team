# G3 人工验证清单

> 按「最可能出问题」排序。每条写清**预期**与**错误表现**，看到错误表现请直接告诉我那句话。
>
> **前置**：插件按 `link:` 安装，源码改动不会热重载。**必须先完整退出并重启 DSH Desktop**，
> 否则看到的一定是旧行为。我改动的 `client.js` 修改时间可以在
> `ds-bot/client.js` 上核对；进程启动时间必须晚于它。

---

## 1. 「Hub 账号」页真的出现在设置里

**怎么做**：打开 Setch 设置（原版 Bot 设置对话框），看左侧导航列表。

**预期**：`密钥` 下面多一条 **`Hub 账号`**，图标是一个带箭头的云。点进去能看到两组卡片：
「Hub 节点」和「登录」。

**错误表现**：
- 没有这一项 → 没有真正重启，或 `client.js` 没有重新构建。
- 有一项但点进去显示的是「General」的内容 → 页面 key 没登记（G2 时出现过同样的 bug，
  `openWorkgroupSettings` 指向了不存在的 page，被静默回退到 General）。
- 整页空白 → 控制台会有报错，请把报错贴给我。

---

## 2. 不填 Hub 地址也能正常用本地功能

**怎么做**：**不要**填写地址，也不要登录。直接关掉设置，用 Chief 发一句话；
再新建一个本地群、发一条消息、@ 一个成员。

**预期**：全部正常，和加这个功能之前完全一样。

**错误表现**：
- 任何一处报错、变灰、转圈不停 → 我破坏了「未登录本地可用」这条，这是我优先要修的。
- 顶部出现红色错误条 → 同上。

---

## 3. 未登录时 Hub 账号页说的是「未登录」而不是报错

**怎么做**：进入 `Hub 账号` 页，不填任何东西。

**预期**：地址框为空（占位符 `https://127.0.0.1:7788`）；「连接状态」写 `未登录`；
有手机号（国家码默认 `+86`）和密码两个输入框；有 `登录` 和 `注册新账号` 两个按钮；
最下面一行 `忘记密码？` 并说明没有找回功能。

**错误表现**：
- 显示红色错误或「加载失败」→ 页面把「未登录」当成了错误，这是我的 bug。
- 一直停在「加载中…」→ `hub-state` 端点没有响应。

---

## 4. 密码输入框不会把密码留在界面上

**怎么做**：在密码框输入任意 10 位以上字符，然后点 `登录`（地址留空即可，会立刻失败）。

**预期**：密码框被**清空**，并出现一条错误提示（`Enter the Hub address first.` 或中文等价）。

**错误表现**：密码还留在框里 → 我没做到「提交后立即清除」，这是我必须修的。

---

## 5. 两次密码不一致时不发请求

**怎么做**：点 `注册新账号`，密码填 `aaaaaaaaaa`，确认密码填 `bbbbbbbbbb`，点 `创建账号`。

**预期**：立刻出现「两次输入的密码不一致。」，**不会有网络请求**（不会转圈很久）。

**错误表现**：转圈后返回一个服务端错误 → 校验放错了位置。

---

## 6. 真的能对着 Hub 登录（需要你先起 Hub）

**怎么做**：在一个终端里：

```bash
cd hub
npm install
HUB_ALLOW_INSECURE_LOCALHOST=1 npm start
```

看到 `{"event":"hub.ready","url":"http://127.0.0.1:7788"}` 后，在页面里：
地址填 `http://127.0.0.1:7788`，手机号填 `13800138000`，密码填 `correct horse battery staple`，
点 `注册新账号` → 填确认密码 → `创建账号`。

**预期**：变成已登录状态，显示脱敏手机号 `+86****8000`、一个 `usr_` 开头的 Hub 用户 ID、
一个 `dev_` 开头的设备 ID、以及凭据存放位置。

**错误表现**（按可能性排序）：
- `无法连接到 Hub (...)` → Hub 没起来，或端口不对。
- `The phone number or password is not correct.` → 你在另一个手机号上已经注册过。
- `A password must be at least 10 characters...` → 密码不够 10 位。
- 卡在注册设备这一步（页面一直转）→ Ed25519 key 生成或签名有问题，请告诉我。

---

## 7. 凭据确实落在本机，且不含密码

**怎么做**：登录成功后，看 `~/.dsh/bot/hub/account.json`（或页面上「凭据存放位置」显示的那个路径）。

**预期**：文件存在，里面有 `refreshToken`（`dsb_rt_` 开头）和 `privateKeyPem`，
**没有** `accessToken`，**没有**你输入的密码。
页面上「凭据存放位置」应该写「仅本人可读的文件」，**不应该**出现「钥匙串」或「keychain」字样。

**错误表现**：
- 文件里能找到明文密码 → 严重 bug，立刻告诉我。
- 文件里能找到完整手机号（`+8613800138000`）→ 也不对，只应有脱敏的。
- 页面写着「OS 钥匙串」→ 文案撒谎了。**这条能力我做不到**（插件取不到 Electron 的
  `safeStorage`），已在 `docs/workgroup/g3/G3-CLOSURE-AUDIT.md` §8 登记为 G6 缺口。

---

## 8. 设置页里的密码字段不会被密码管理器/自动填充误伤

**怎么做**：浏览器或系统如果弹「保存密码」提示，观察它保存的是什么。

**预期**：它保存的是 Hub 账号的手机号 + 密码——那是对的，是给人用的登录表单。
**但插件本地**不会留下这份副本。

**错误表现**：如果提示保存的是 DSH 自身凭据而不是 Hub 账号，请告诉我，我会给输入框加隔离属性。

---

## 9. 两台「机器」= 同一个 hubUserId（可在一台机器上模拟）

**怎么做**：登录状态下，点 `显示设备列表`，应看到当前这台机器一行。
想验证换机：把 `~/.dsh/bot/hub/account.json` 改名备份（模拟新机器），页面会变回未登录；
重新用**同一个手机号**登录。

**预期**：Hub 用户 ID **不变**，设备列表里出现**第二行**（旧设备仍在，不是消失），
当前设备那一行标着「本机」。

**错误表现**：
- Hub 用户 ID 变了 → 身份稳定性失败，这是门禁 2 的核心，必须修。
- 设备列表只有一行（旧的消失）→ 我把「换机会踢掉旧设备」和「撤销」搞混了。

---

## 10. 撤销一台设备，它立刻掉线

**怎么做**：在设备列表里，对**不是本机**的那一行点 `撤销`。

**预期**：那一行的 `撤销` 消失（带 `revokedAt`），本机不受影响。

想看「即时断线」本身则需要一台真的第二台机器或第二个 DSH 实例——G3 的 WSS 只为证明
这一点而存在，界面上没有常驻连接状态可看。这条的自动化证据是
`hub/test/ws-revoke.test.js`，实测 2ms 内 `close(4401)`。

**错误表现**：点撤销报错 `No such device.` → 设备 id 传错了。
点撤销后本机也掉线 → 撤销逻辑认错了当前设备。

---

## 11. 退出登录后，本地一切照旧

**怎么做**：点 `退出登录`，然后把第 2 条（本地发消息、建群）**再走一遍**。

**预期**：账号信息消失，页面回到未登录；本地功能**完全没有变化**；`account.json` 已删除。

**错误表现**：退出后本地功能变差或报错 → 门禁 5 在退出路径上被破坏。

## 12. Hub 关掉之后，页面不崩、本地不崩

**怎么做**：保持登录状态，Ctrl-C 停掉 Hub 进程，然后：进 `Hub 账号` 页 → 点 `显示设备列表`；
再去发一句本地消息。

**预期**：设备列表报一条可读的错误（`Could not reach the Hub`）；页面其余部分仍可用；
**本地发消息完全正常**。重新启动 Hub 后，点 `显示设备列表` 能恢复（refresh token 会自动换新
access token）。

**错误表现**：
- 整个设置页白屏 → 我把网络错误当成了致命错误。
- 本地消息发不出去 → 门禁 5 在离线路径上被破坏，必须修。

---

## 13. 手机号不会被当成「已验证」

**怎么做**：登录后看页面上关于手机号的每一处文字。

**预期**：只显示脱敏号 `+86****8000`，**任何地方都没有**绿色勾、「已验证」「已认证」字样。
未登录时手机号输入框下面的说明写着「只作为登录名使用，未经验证——这个 Hub 不发送短信」。

**错误表现**：出现任何「已验证」或对勾 → 文案撒谎了，必须改。
这条不是我多虑：数据库里 `phone_verified_at` 字段一直在且恒为 NULL，过两三个阶段一定会有人
照着字段名写出「已验证」。

## 14. 登录后能改密码（第一层找回）

**怎么做**：登录状态下，`Hub 账号` 页 →「密码」卡片：填当前密码、新密码、确认新密码 → `修改密码`。

**预期**：出现「密码已修改，其他所有会话已退出登录。」；页面保持登录（拿到新 token）；
下次用新密码能登录，旧密码不行。

**错误表现**：
- 报 `当前密码不正确` → 输入错了；若确认没输错，说明我用错了校验字段。
- 改完被踢回未登录 → 我丢了新会话，`evictAndIssue` 有问题。
- 报 `the same password` → 新密码和旧的一样（这是有意的拒绝）。

## 15. 生成恢复码，且只显示一次

**怎么做**：登录状态下，「恢复码」卡片 → `生成恢复码`。

**预期**：出现一个 `XXXX-XXXX-XXXX-XXXX` 格式的 16 位码，下面写「现在就抄下来并妥善保存。它只会
显示这一次。」**离开页面再回来，码不再显示**（卡片只显示「你有一个未使用的恢复码」）。

**错误表现**：
- 返回页面还能看到码 → 我把它存下来了，这是严重的安全问题，立刻告诉我。
- 码里有 `0`、`1`、`I`、`O` → 字母表用错了（这四个字符会让手抄出错）。
- 点了没反应或报错 → 看是否 Hub 已停。

## 16. 用恢复码在「新机器」上找回（第二层）

**怎么做**：
1. 先完成第 15 条拿到一个码。
2. 把 `~/.dsh/bot/hub/account.json` 备份后**删掉**（模拟新机器）→ 页面变未登录。
3. 点「用恢复码找回」，填：地址、手机号、恢复码、新密码、确认新密码 → `找回账号`。

**预期**：变成已登录，**同一个 `hubUserId`**，但**新的 `deviceId`**；旧密码登录失败（如果之前
改过）；**同一个恢复码再用一次会失败**（`该恢复码无效，或已被使用`）。

**错误表现**：
- 报 `恢复码无效` → 检查是否抄错（注意 `I/O/0/1` 本来就不会出现）、或这个码已经用过。
- 找回后 `hubUserId` 变了 → 严重 bug，说明我建了新账号。
- 码能重复使用 → 单次性失效。

## 17. 恢复后旧机器被踢出

**怎么做**：两台机器（或同一台的两个存储目录）都登录同一账号；在 A 上执行第 16 条的找回流程。

**预期**：B 的下一次操作报「会话已退出」或要求重新登录；A 正常可用。

**错误表现**：B 还能继续操作 → 找回没有结束其他会话，这是找回功能的核心语义，必须修。

## 18. 什么都没有时的运维重置（第三层）

**怎么做**（需要一个终端，Hub 数据目录在 `hub/.data`）：

```bash
cd hub
node src/cli.js show  --phone +8613222222222
node src/cli.js reset --phone +8613222222222 --password 'a brand new passphrase'
```

**预期**：`show` 打印 `hubUserId`、脱敏号、未用恢复码数量，**不打印**完整手机号、不打印
`$scrypt$` 哈希；`reset` 打印「password reset for +86****2222」，**不回显密码**。
重置后旧密码失效、所有会话被踢。

**错误表现**：
- 提示 `no database at ...` → 数据目录不对，用 `HUB_DATA_DIR` 指定。
- 提示 `no account with that phone number` → 号码没注册过或格式不是 E.164（要 `+86` 前缀）。
- 命令把密码打印出来了 → 严重，请立刻告诉我（终端回滚缓冲区就是文件）。
