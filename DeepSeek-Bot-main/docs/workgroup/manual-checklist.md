# 人工验收清单（G3 水位）

> 执行人：维护者。AI 不对判断类项目下结论。每条给出「怎么做 / 看到什么算通过 / 看到什么算失败」。

## 1. 插件形态：工作群入口与面板

- **怎么做**：在本机启动 DSH（或 `npx @deepseek-ai/dsh web`），启用 ds-bot，打开 Bot 界面。
- **算通过**：侧栏出现「Bot」入口；进入后能看到工作群面板与空态；面板顶部有「未完成：工作群聊天与消息尚未提供」的声明。
- **算失败**：入口不出现；面板报错；声明缺失或写着"可以使用"。

## 2. 本地群零回退

- **怎么做**：用两个 Bot 建一个本地群，发一条不 `@` 的消息，再 `@` 其中一个；观察谁回答、顺序、底部卡片；停止一次回合。
- **算通过**：与迁移前的行为一致（管理员先答或全员轮流、发言顺序、`@` 只叫被点名者、停止生效）。
- **算失败**：任何一项行为与升级前不同，或本地群列表里混入工作群。

## 3. 工作群行与原版群行并存

- **怎么做**：创建一个工作群（若 Hub 未配置，先看第 4 条）。
- **算通过**：侧栏列表里工作群行与本地群行混排、样式一致、悬停显示完整名称；右键菜单有「Workgroup settings / Rename group / Delete」，本地群右键多出「Upgrade to a workgroup」。
- **算失败**：工作群出现在「其他对话」里；点工作群行报「Unknown group chat」；右键菜单项缺失。

## 4. 未登录 Hub 的降级

- **怎么做**：不登录 Hub，直接使用本地群、私聊、设置。
- **算通过**：全部可用；工作群面板显示"未连接"与原因，不阻塞任何本地操作。
- **算失败**：任何本地功能因 Hub 不可用而失效或报错。

## 5. Hub 账号页

- **怎么做**：设置 → Hub account；填一个不可达地址并提交；再用本地 Hub 的 `HUB_ALLOW_INSECURE_LOCALHOST=1 npm start` 启动一个实例并登录。
- **算通过**：不可达时给出可行动的失败原因（拒绝连接 / 证书 / 域名解析），不是 "fetch failed"；登录后显示账号与设备列表；页面**不出现**"已验证"或"钥匙串"字样。
- **算失败**：错误不可读；页面声称手机号已验证；页面声称凭据在 OS 钥匙串。

## 6. 桌面应用形态

- **怎么做**：在 `app/` 下重新 `npm ci`（`ds-bot` 以包文件复制），启动桌面应用。
- **算通过**：工作群入口与面板以与插件相同的形态出现，没有第二套窗口或入口；`ds-bot` 与 `app` 版本仍为 0.2.0。
- **算失败**：桌面端看不到工作群，或出现独立窗口/入口。

## 7. 未完成能力的边界（G4 项）

- **怎么做**：在工作群面板尝试创建群 / 发送消息（Hub 已启动但无群与消息持久化）。
- **算通过**：失败信息明确，不假装成功、不静默丢消息；文案与"未完成"声明一致。
- **算失败**：界面显示成功但 Hub 没有数据；或消息静默消失。
