## 已接受，必须在 G6 处理

### 1. 设备私钥与 refresh token 存在 0600 凭据文件，不是 OS 钥匙串

| | |
|---|---|
| **方案原文要求** | §7.3「私钥留在 OS 安全存储」；§12「OS 密钥链保存私钥/刷新凭证，客户端页面不能直接拿到长期私钥」 |
| **实际实现** | 优先写 Harness 的 `ctx.credentials` 接缝（`$DSH_HOME/.credentials.yaml`，0600，接缝自身拒绝组/他人可读）；该服务不存在时写 `~/.dsh/bot/hub/account.json`（0600，写前校正权限） |
| **为什么做不到** | 插件宿主进程里 `require('electron')` 解析不到，取不到 `safeStorage`；Node 没有内置钥匙串；接 Windows DPAPI / macOS Keychain 必须引原生模块，与「仓库只两个一级代码目录 + 最小依赖」冲突 |
| **页面是否如实说明** | 是。设置页只写「Harness 凭据存储（仅本人可读的文件）」或「Bot 数据目录下仅本人可读的文件」，**不出现「钥匙串」「keychain」字样**，并有测试守着这两个词 |
| **决定人 / 时间** | 用户，2026-10-22（回答「受并记 G6」） |
| **处理阶段** | **G6** |
| **G6 要看什么** | DSH 是否已向插件暴露 `safeStorage` 或等价接缝。如果暴露了，这是一次纯替换：`hub-store.js` 的 `backend` 从 `credentials`/`file` 增加第三种，读写接口不变，测试补一条 |
| **风险等级** | 中。文件是 0600，但同机同用户的其他进程可读；它不是加密边界，只是权限边界 |

## 长期如此（由产品决定，不是缺口）

### 2. 手机号未经任何验证

| | |
|---|---|
| **事实** | `users.phone_verified_at` 恒为 NULL。V1 不发送任何短信 |
| **为什么** | 用户决定用手机号 + 密码注册登录，不做 OTP（见 `docs/workgroup/g3/NEXT-INSTRUCTION.md`「认证方式变更」） |
| **后果** | 手机号是**登录名**，不是已验证身份。任何代码/UI/文档不得声称「已验证」，不得做已验证角标 |
| **守住它的机制** | `test/hub-account-switch.test.js` 的「the page never claims the phone number is verified」断言页面与文案里每一处出现 verified 的地方都是免责声明 |
| **决定人** | 用户 |
