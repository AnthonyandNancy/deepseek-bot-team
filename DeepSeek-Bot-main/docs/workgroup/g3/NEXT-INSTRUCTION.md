### A. Hub 服务（hub/）

1. **HTTP 服务 + 数据库迁移**。V1 用 SQLite（WAL、外键开、`busy_timeout`、迁移版本号），
   按方案 §12 建表。G3 只需要这些表真正被用到：`users`、`auth_sessions`、`devices`、
   `audit_events`。其余表（workgroups/memberships/events/deliveries/…）可以建空表并带
   迁移，但**不要**在 G3 实现它们的业务逻辑（那是 G4）。**不建 `otp_challenges`。**
2. **认证端点**（在方案 §13.1 草案基础上按密码制调整，端点路径保持 `/v1/auth/*` 风格）：
   - `POST /v1/auth/register`  手机号 + 密码 → 建用户 + 建会话
   - `POST /v1/auth/login`     手机号 + 密码 → 建会话
   - `POST /v1/auth/refresh`   刷新轮换（旧 refresh 立即失效）
   - `POST /v1/auth/logout`    吊销当前会话
   - `GET  /v1/auth/me`        返回 `hubUserId`、脱敏手机号、会话与设备摘要
3. **密码存储**：只用 `node:crypto` 的 `scrypt`（不引原生依赖），每用户独立随机盐，
   参数写进代码常量并记录在 README；校验用 `timingSafeEqual`。**任何地方不得出现明文
   或可逆存储**；`users` 表只存 `password_hash`、`password_salt`（或合并的 PHC 字符串）
   与参数版本号，便于以后升级算法。密码策略：长度 ≥10、≤128 字节，拒绝与手机号数字
   完全相同的密码；**不做**强制大小写/符号组合的要求。
4. **账号枚举的取舍要显式处理**：注册时重复手机号可以返回"该手机号已注册"（否则用户
   无从得知），但该端点必须限流并进 `audit_events`；**登录失败一律返回同一句
   "手机号或密码不正确"**，不区分"用户不存在"与"密码错误"，且两条路径耗时不得有
   明显差异（不存在时也跑一次假校验）。
5. **设备端点**：`POST /v1/devices/challenge`、`POST /v1/devices/register`、
   `GET /v1/devices`、`POST /v1/devices/:id/revoke`。设备密钥用 Ed25519，
   服务端只存公钥，私钥永不离开客户端。
6. **WSS 最小服务**：握手绑定 `{hubUserId, deviceId}`，设备撤销必须**即时断线**。
   G3 的 WSS 只需要能证明这一点（握手 + 撤销踢线 + 心跳），不需要消息扇出（G4）。
7. **访问日志脱敏**：日志不得出现完整手机号（允许保留末四位或哈希前缀）、密码明文、
   任何 token、设备私钥。要有测试断言这一点（喂一个含敏感值的请求，断言日志产物里
   不含原值）。
8. 允许的依赖保持最少：`ws` 用于 WSS 可以接受；SQLite 优先用 Node 内置 `node:sqlite`，
   若确有不可用原因才引入 `better-sqlite3`，并在 README 写明理由。**不要为了少写代码

## 起草说明（不用发给执行方）

**为什么改了认证方式还要这么多话。** 手机号+密码不是"少写一点代码"这么简单，它把
方案里一个已经想清楚的东西换掉了：

- 原设计的 `phone_verified_at` 是有意义的（真的验证过）；密码制下它永远为 NULL，
  所以我在指令里反复禁止"已认证"字样——否则过两个阶段就会有人照着字段名写出一句
  "手机号已验证"，而那是假的。
- 原设计里 OTP 是一次性凭证，被截获只损失一次；密码是永久凭证。所以我把 TLS 从
  "证书配置"提升成硬性要求，并只留 localhost 明文例外。这一条不加，密码制就是在
  裸奔。
- 原设计里忘记密码靠短信自证，现在没了。你选了"不做找回"，指令里照做，但我要求
  把它写进缺口表并注明"G4 前必须补"——因为 G3 阶段 Hub 里没有真实业务数据，丢了
  等于重注册；G4 之后丢了就是丢工作群。现在决定不等于以后不用决定。

**门禁表怎么改的。** 原三条 OTP 项不是删除，是"标记不适用 + 用等价条目替代"，
两个都写进指令，这样将来谁翻回去都能看出这里变过。替代条目保留了原三条想验证的
真实意图：两个手机号是两个身份、同一手机号换机身份不变、错误凭据被拒。

**`node:sqlite` 还是 `better-sqlite3`。** 我没有替你定死。Node v24 自带 `node:sqlite`，
用它可以让 `hub/` 只依赖一个 `ws`；但它在这个版本上可能有 experimental 警告。指令里
让执行方按实际可用性选，并说明理由——这种事写死反而容易踩坑。

**基线数字**（791 passed）会随工作变化，执行方应以当时的实际输出为准。
